## 1. 产品概述

### 1.1 产品愿景
打造一个真正智能的、对话式的笔记系统，让用户专注于内容记录，由 AI 负责自动整理、分类、追踪和检索，实现从记录到行动的无缝转化。

### 1.2 核心理念
- **零负担输入**: 用户只需写，无需考虑分类、格式、结构
- **智能理解**: AI 自动理解内容类型、提取关键信息、建立关联
- **对话式检索**: 用自然语言提问，AI 智能整理并展示结果
- **快速转化**: 从笔记到待办、日程的一键转化

### 1.3 目标用户
- 工作中需要记录大量碎片化信息的知识工作者
- 不喜欢复杂笔记结构和分类的用户
- 希望通过自然语言快速检索历史信息的用户
- 需要将笔记内容快速转化为行动项的用户

## 2. 功能需求

### 2.1 核心功能

#### 2.1.1 自由记录 (Core-F01)

**功能描述**  
提供极简的内容输入界面，用户可以随时随地记录任何内容，无需选择分类或格式。

**用户场景**
- 用户打开应用，看到一个干净的输入框
- 用户直接输入内容，例如：
    - "今天客户 A 反馈说登录功能有问题，需要排查"
    - "下周需要和产品团队开会讨论新需求"
    - "学习了 Python 的装饰器，记录一下关键点..."
- 用户点击保存，内容自动提交

**功能要点**
- 支持 Markdown 格式
- 支持快捷键保存 (Ctrl/Cmd + S)
- 自动保存草稿（每 30 秒）
- 显示字数统计
- 时间戳自动记录

**验收标准**
- [ ] 输入框加载时间 < 500ms
- [ ] 支持 Markdown 实时预览
- [ ] 草稿自动保存功能正常
- [ ] 快捷键响应正常

---

#### 2.1.2 AI 智能分析 (Core-F02)

**功能描述**  
每次用户提交笔记后，后台 AI 自动分析内容，提取结构化信息并分类存储。

**AI 分析维度**

1. **内容分类**
    - 学习笔记
    - 工作记录
    - 客户问题
    - 需求记录
    - Bug 记录
    - 会议记录
    - 想法灵感
    - 个人杂记

2. **关键信息提取**
    - 涉及人物/公司/团队
    - 时间信息（截止日期、会议时间）
    - 状态标记（待处理/进行中/已完成/待确认）
    - 优先级（高/中/低）
    - 主题/标签

3. **特殊类型识别**
    - 是否包含待办任务
    - 是否需要安排日程
    - 是否需要跟进

4. **关联建立**
    - 与历史笔记的关联（相同项目、相同客户、相同主题）
    - 相关笔记推荐

**用户场景**
- 用户输入："明天下午 3 点要和张三讨论 APP 改版需求，他提到要加入暗色模式"
- AI 自动识别：
    - 类型：会议记录 + 需求记录
    - 时间：明天 15:00
    - 人物：张三
    - 主题：APP 改版、暗色模式
    - 状态：待确认
    - 建议：是否创建日程提醒？

**技术要求**
- AI 分析响应时间 < 3 秒
- 分类准确率目标 > 85%
- 支持中文内容理解

**验收标准**
- [ ] AI 能正确识别至少 8 种内容类型
- [ ] 能准确提取时间、人物、状态信息
- [ ] 分析结果以结构化数据存储
- [ ] 用户可查看 AI 的分析结果

#### 2.1.3 对话式检索 (Core-F03)

**功能描述**  
用户通过自然语言提问，系统智能检索相关笔记并整理展示。

**用户场景示例**

**场景 1：查询待办事项**
- 用户问："有哪些需求问题还没有确定？"
- 系统响应：
    - 检索所有"需求记录"类型 + "待确认"状态的笔记
    - AI 整理成列表展示
    - 显示创建时间、相关人物、优先级
    - 提供快速操作：标记为已确认、创建 Todo、查看详情

**场景 2：按时间范围查询**
- 用户问："上周和客户 A 相关的问题有哪些？"
- 系统响应：
    - 时间范围：上周
    - 关键词：客户 A
    - 展示相关笔记时间线
    - 标注问题状态（已解决/待处理）

**场景 3：主题聚合**
- 用户问："我学了哪些关于 Python 的知识？"
- 系统响应：
    - 检索所有包含 "Python" 的学习笔记
    - 按主题分组（基础语法、装饰器、异步编程...）
    - 生成学习路径图

**场景 4：跨维度查询**
- 用户问："本周需要开哪些会？"
- 系统响应：
    - 筛选本周 + 会议类型的笔记
    - 按时间排序
    - 显示会议主题、参与人、地点
    - 提供一键添加到日历功能

**交互要求**
- 检索结果响应时间 < 2 秒
- 支持多轮对话（追问、筛选、细化）
- 结果可排序（按时间、优先级、相关度）
- 支持导出检索结果

**验收标准**
- [ ] 能理解常见的查询意图（时间、人物、主题、状态）
- [ ] 检索准确率 > 80%
- [ ] 支持至少 5 种查询模式
- [ ] 结果展示清晰、可操作

#### 2.1.4 快速转化为行动项 (Core-F04)

**功能描述**  
从笔记或检索结果中，一键创建待办事项（Todo）或日程安排（Schedule）。

**功能点 1：创建 Todo**

**触发方式**
- 从单条笔记创建
- 从检索结果批量创建
- AI 主动建议（识别到任务性内容时）

**创建流程**
1. 用户选择笔记或点击"创建 Todo"
2. AI 自动填充：
    - 任务标题（从笔记内容提取）
    - 截止日期（如果笔记中有时间信息）
    - 优先级（根据内容判断）
    - 描述（关联原笔记）
3. 用户可编辑后确认
4. Todo 添加到待办列表

**用户场景**
- 用户查询："有哪些需求还没确定？"
- 系统展示 3 条结果
- 用户选中其中 2 条，点击"创建 Todo"
- 系统生成 2 个待办任务：
    - "确认 APP 改版需求 - 暗色模式"（优先级：高，截止：本周五）
    - "和产品讨论用户反馈功能"（优先级：中，截止：下周）

**功能点 2：创建 Schedule**

**触发方式**
- 从会议类笔记创建
- 从 Todo 创建（需要安排具体时间）
- 手动创建

**创建流程**
1. AI 提取会议信息：
    - 会议主题
    - 参与人
    - 时间（日期 + 具体时间）
    - 地点/链接
    - 议程（从笔记生成）
2. 用户确认/编辑
3. 添加到日程表
4. （可选）发送邮件/通知给参与人

**用户场景**
- 用户笔记："明天下午 3 点和张三、李四讨论 Q2 规划，需要准备上季度数据"
- AI 识别后提示："检测到会议信息，是否创建日程？"
- 用户确认，系统自动创建：
    - 主题：Q2 规划讨论会
    - 时间：明天 15:00
    - 参与人：张三、李四
    - 待办：准备上季度数据

**验收标准**
- [ ] 可从笔记一键创建 Todo
- [ ] 可从笔记一键创建 Schedule
- [ ] AI 自动填充准确率 > 80%
- [ ] 创建后关联原笔记
- [ ] Todo 和 Schedule 支持编辑、删除、状态更新

## 6. 用户故事

### 6.1 核心用户故事

**Story 1: 工作记录者 - 小李**
- **背景**: 小李是产品经理，每天要记录大量客户反馈、需求讨论
- **痛点**: 信息散乱，经常找不到之前的讨论内容
- **使用场景**:
    1. 早上收到客户邮件，打开笔记本随手记录："客户 A 反馈登录慢，需要优化"
    2. 下午开会，记录："和技术讨论，登录优化预计 2 周完成，优先级高"
    3. 第二天想起来，问系统："客户 A 的问题进展如何？"
    4. 系统自动整理展示相关记录，小李一目了然
    5. 小李创建 Todo："2 周后跟进客户 A 反馈登录优化结果"

**Story 2: 学习者 - 小王**
- **背景**: 小王在学习编程，经常记录学习笔记
- **痛点**: 笔记太多，复习时不知道从哪里开始
- **使用场景**:
    1. 学习时随手记录："Python 装饰器的本质是高阶函数..."
    2. 几天后学到新内容："闭包的概念和装饰器有关系"
    3. 复习时问系统："我关于 Python 装饰器学了什么？"
    4. 系统自动关联相关笔记，形成知识脉络
    5. 小王基于整理的内容制定复习计划

**Story 3: 团队管理者 - 小张**
- **背景**: 小张管理 5 人团队，需要跟进多个项目
- **痛点**: 会议多、任务多，容易遗漏
- **使用场景**:
    1. 周一晨会记录："项目 A 本周要完成功能测试，负责人小赵"
    2. 周三客户会记录："客户要求下周五前看到 Demo"
    3. 周四问系统："本周还有哪些待办没完成？"
    4. 系统列出：项目 A 测试（小赵）、Demo 准备
    5. 小张创建 Schedule："明天和小赵 1-on-1 确认测试进度"

## 8. 风险和挑战

### 8.1 技术风险
- **AI 理解准确性**: 中文理解、特定领域术语识别可能不准确
    - 缓解措施：允许用户手动修正，系统学习反馈

- **性能问题**: 笔记量大时检索速度可能下降
    - 缓解措施：使用向量数据库优化，增加缓存机制

- **API 成本**: Claude API 调用成本可能较高
    - 缓解措施：本地缓存分析结果，批量处理，提供本地模型选项

### 8.2 用户体验风险
- **学习曲线**: 用户可能不习惯对话式检索
    - 缓解措施：提供常用查询模板，引导用户

- **过度依赖 AI**: AI 分类错误可能误导用户
    - 缓解措施：始终显示原始笔记，允许手动调整

### 8.3 数据风险
- **数据丢失**: 本地存储可能因故障丢失
    - 缓解措施：自动备份机制，导出功能

- **隐私问题**: 笔记发送到 Claude API
    - 缓解措施：明确告知用户，提供本地模型选项，敏感内容不上传
